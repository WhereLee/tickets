# 阶段二教学计划：Redis 缓存与并发优化

> 学习方式：老师（助手）讲原理 → 学生提问 → 实现 → 验证 → 留存
> 目标：解决阶段一极限压测暴露的三大瓶颈（行锁 / Tomcat 容量 / 连接池）

---

## 阶段一回顾（压测基线）

| 瓶颈 | 触发点 | 现象 |
|------|--------|------|
| 行锁串行化 | 1 并发就存在 | 34ms → 100 并发 430ms |
| Tomcat 容量 | 200 并发 | 47.5% 连接被拒 |
| 连接池 10 | 500 并发 | 响应飙到 1301ms |
| 系统极限 | ≈ 100 并发 | 超过则被拒或极慢 |

---

## 教学步骤（每步：原理 → 实现 → 验证 → 留存）

### 步骤 1：认识 Redis（纯理论，不写代码）
- Redis 是什么？为什么快？（内存 vs 磁盘）
- 数据结构：String / Hash / List / Set / ZSet
- 我们场景用到哪些？为什么？

### 步骤 2：引入 Redis（环境 + 依赖）
- 本机 Redis 安装/启动（F:\Redis 已有）
- pom.xml 加依赖、application.yml 配置
- RedisTemplate 序列化配置
- 验证：连接成功，读写一个 key

### 步骤 3：活动信息缓存（读路径优化）
- 查询活动从"查数据库"改为"先查 Redis"
- 问题：缓存和数据库一致性？缓存穿透？
- 验证：活动接口响应时间对比

### 步骤 4：库存预扣减（核心！写路径优化）
- Redis DECR 原子操作：为什么能解决行锁？
- Lua 脚本：判断 + 扣减的原子性
- 和数据库库存的关系（预扣减 + 异步同步）
- 验证：压测对比行锁瓶颈是否消失

### 步骤 5：抢购流程改造（组合拳）
- 完整新流程：Redis 判断资格 → 建订单 → 同步库存
- 取消/过期时 Redis 库存回滚
- 问题：Redis 库存和数据库库存不一致怎么办？
- 验证：功能测试 + 并发测试

### 步骤 6：参数调优（基础设施）
- HikariCP 连接池：调大 + 原理（为什么不是越大越好）
- Tomcat 线程池：maxThreads/acceptCount
- 验证：500 并发下被拒率变化

### 步骤 7：修复已知问题（质量）
- DuplicateKeyException → 友好提示
- 幂等校验优化（直接插入，冲突即拒绝）
- 密码加密（BCrypt）

### 步骤 8：阶梯复测对比（收尾）
- 同样的 9 档阶梯压测（50→2000）
- 对比曲线：极限从 100 并发提升到多少？
- 阶段总结 + Git 提交

## 教学原则

1. **先原理后代码**：每步先用大白话讲清楚"为什么"，学生确认理解后再写代码
2. **随时提问**：学生有疑问随时打断，老师耐心解答，解答后继续
3. **留存优先**：每个动作完成后先记录，再进入下一步
4. **数据说话**：每步的改进必须用压测数据验证，不做无依据的优化
