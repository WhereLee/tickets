# Java 开发面试高频考点与项目设计指南

## 一、项目设计总纲：从哪些维度思考一个系统

在设计面试项目时，需要从以下 **8 个维度** 去审视系统，每个维度都对应一组面试高频考点。

---

### 1. 查询效率 —— 数据怎么查得快

> 核心问题：用户量大了、数据量大了，系统还能不能秒回？

| 关注点 | 要解决的问题 |
|--------|-------------|
| 索引设计 | 数据量大了怎么查？B+ 树原理？联合索引最左匹配？索引失效场景？ |
| 缓存策略 | 每次都查数据库扛不住，热点数据放 Redis？缓存和数据库怎么保持一致？ |
| 读写分离 | 读多写少的场景，主库写、从库读？主从延迟怎么处理？ |
| 分库分表 | 单表数据量到千万级了怎么办？水平拆分还是垂直拆分？分片键怎么选？ |

---

### 2. 并发处理 —— 很多人同时操作怎么办

> 核心问题：1000 个人同时抢 10 张票，怎么保证不出错？

| 关注点 | 要解决的问题 |
|--------|-------------|
| 线程安全 | 多个线程同时修改同一个数据，会不会出问题？synchronized、Lock 怎么用？ |
| 线程池 | 每个请求都开一个线程太浪费，线程池怎么设计？参数怎么调？ |
| 锁机制 | 乐观锁 vs 悲观锁？什么场景用哪个？CAS 是什么？ |
| 库存超卖 | 高并发下怎么防止多卖？Redis 预扣减？数据库行锁？ |

---

### 3. 数据一致性 —— 多个操作怎么保证不出错

> 核心问题：用户付了钱但订单没创建成功，钱退不退？

| 关注点 | 要解决的问题 |
|--------|-------------|
| 本地事务 | ACID 是什么？事务隔离级别？MySQL 默认哪个级别？为什么？ |
| 分布式事务 | 跨服务、跨库的操作怎么保证一致性？2PC、TCC、消息最终一致性？ |
| 幂等设计 | 用户手抖点了两次支付，会不会扣两次钱？接口怎么防重？ |
| 数据补偿 | 出错了怎么回滚？重试机制怎么设计？死信队列怎么处理？ |

---

### 4. 系统可用性 —— 挂了怎么办

> 核心问题：某个服务突然挂了，用户还能不能用系统？

| 关注点 | 要解决的问题 |
|--------|-------------|
| 服务降级 | 系统扛不住了，哪些功能可以先砍掉保核心？ |
| 熔断机制 | 下游服务挂了，上游一直等会拖垮整个系统，怎么及时断开？ |
| 限流 | 突然来了一百万请求，怎么保护系统不被打垮？令牌桶？滑动窗口？ |
| 多活部署 | 一个机房挂了，另一个机房能立刻顶上吗？ |

---

### 5. 安全与鉴权 —— 谁能干什么

> 核心问题：怎么保证 A 用户不能操作 B 用户的订单？

| 关注点 | 要解决的问题 |
|--------|-------------|
| 认证 | 用户登录怎么验证身份？JWT 还是 Session？Token 过期了怎么办？ |
| 授权 | 普通用户和管理员能做的事不一样，权限怎么控制？RBAC 模型？ |
| 接口安全 | 怎么防止接口被恶意调用？签名校验？防重放攻击？ |
| 敏感数据 | 密码能明文存吗？加密方案怎么选？（BCrypt、AES） |

---

### 6. 消息与异步 —— 不需要立刻做完的事怎么搞

> 核心问题：下单后要发短信、加积分、通知商家，全同步做太慢了怎么办？

| 关注点 | 要解决的问题 |
|--------|-------------|
| 异步解耦 | 下单成功就行，后面的事扔给消息队列慢慢处理 |
| 削峰填谷 | 秒杀时请求太多，消息队列先排队，系统按能力慢慢消费 |
| 消息可靠性 | 消息丢了怎么办？消息重复消费了怎么办？顺序消息怎么保证？ |
| 延迟任务 | 订单 30 分钟不支付就自动取消，怎么实现？延迟队列 |

---

### 7. 可扩展性 —— 以后加功能方不方便

> 核心问题：老板说下周要加个优惠券功能，代码要改多少地方？

| 关注点 | 要解决的问题 |
|--------|-------------|
| 微服务拆分 | 哪些功能该拆成独立服务？怎么拆才不会互相耦合？ |
| 接口设计 | RESTful 规范？版本管理？向前兼容？ |
| 设计模式 | 策略模式、模板方法、责任链……怎么让代码更容易扩展？ |
| 配置管理 | 改个参数还要重新发版？配置中心怎么搞？ |

---

### 8. 可观测性 —— 出了问题能不能快速定位

> 核心问题：用户说"我的订单查不到了"，你怎么找到问题在哪？

| 关注点 | 要解决的问题 |
|--------|-------------|
| 日志规范 | 日志怎么打？级别怎么分？链路追踪 ID 怎么传？ |
| 监控告警 | CPU 飙了、接口慢了，怎么第一时间知道？ |
| 链路追踪 | 一个请求经过了 5 个服务，哪个环节出了问题？ |
| 性能调优 | 怎么定位慢 SQL？JVM 内存泄漏怎么排查？ |

## 二、面试高频问题清单

### 2.1 Java 基础与进阶

| 主题 | 高频问题 |
|------|---------|
| **集合框架** | HashMap 底层原理？ConcurrentHashMap 如何实现线程安全？ArrayList 和 LinkedList 区别？ |
| **JVM** | JVM 内存模型？GC 算法和垃圾回收器？类加载机制？如何排查 OOM？ |
| **并发编程** | synchronized 与 ReentrantLock 区别？线程池参数？volatile 关键字？CAS 原理？AQS 框架？ |
| **IO/NIO** | BIO、NIO、AIO 区别？零拷贝原理？ |

### 2.2 Spring 生态

| 主题 | 高频问题 |
|------|---------|
| **Spring Core** | IOC 容器启动流程？Bean 生命周期？循环依赖如何解决？AOP 实现原理？ |
| **Spring Boot** | 自动配置原理？Starter 机制？内嵌 Tomcat 启动流程？ |
| **Spring MVC** | 请求处理全链路？拦截器 vs 过滤器？异常处理机制？ |
| **Spring 事务** | 事务传播行为？@Transactional 失效场景？ |

### 2.3 数据库与缓存

| 主题 | 高频问题 |
|------|---------|
| **MySQL** | 索引数据结构（B+树）？事务隔离级别？MVCC 原理？慢 SQL 优化？分库分表方案？ |
| **Redis** | 数据结构与使用场景？持久化策略（RDB/AOF）？缓存穿透/击穿/雪崩？分布式锁？集群方案？ |
| **连接池** | HikariCP 原理？数据库连接池参数调优？ |

### 2.4 分布式系统

| 主题 | 高频问题 |
|------|---------|
| **微服务** | 服务注册与发现？负载均衡？熔断降级（Sentinel/Hystrix）？链路追踪？ |
| **分布式事务** | 2PC、TCC、Saga、消息最终一致性？Seata 原理？ |
| **消息队列** | Kafka/RocketMQ 架构？如何保证消息不丢失？顺序消息？重复消费？ |
| **分布式锁** | Redis 分布式锁（Redisson）？Zookeeper 分布式锁？ |

### 2.5 系统设计

| 主题 | 高频问题 |
|------|---------|
| **高并发** | 如何设计一个秒杀系统？限流方案？ |
| **高可用** | 如何实现服务降级？多活架构？ |
| **场景题** | 设计短链系统？设计订单超时取消？设计接口幂等？ |

## 三、推荐项目：在线票务系统

### 3.1 项目架构

```
┌─────────────────────────────────────────────────┐
│                  网关层 (Gateway)                 │
│         限流 / 鉴权 / 路由 / 灰度发布             │
├─────────────────────────────────────────────────┤
│  用户服务 │ 票务服务 │ 订单服务 │ 支付服务 │ 通知服务 │
├─────────────────────────────────────────────────┤
│     Redis      │   MySQL(分库分表)  │  MQ(RocketMQ)│
├─────────────────────────────────────────────────┤
│   分布式锁     │   分布式事务       │  链路追踪     │
└─────────────────────────────────────────────────┘
```

### 3.2 功能模块与面试考点映射

| 功能模块 | 覆盖的面试考点 |
|---------|--------------|
| **登录注册** | JWT、Spring Security、Redis 会话、接口幂等 |
| **抢票/秒杀** | 并发编程、Redis 分布式锁、Lua 脚本、限流、消息队列异步下单 |
| **订单系统** | 分布式事务（TCC/消息最终一致性）、延迟队列（超时取消）、状态机 |
| **支付模块** | 分布式事务、幂等设计、回调重试 |
| **库存扣减** | Redis 预扣减、数据库乐观锁、防超卖 |
| **消息通知** | MQ 消息可靠性、重试机制、死信队列 |
| **数据查询** | MySQL 索引优化、分库分表（ShardingSphere）、Redis 缓存策略 |
| **接口设计** | 幂等性、防重提交、限流（令牌桶/滑动窗口） |

### 3.3 亮点功能（面试加分项）

1. **手写简易版核心组件**：简易 IOC 容器、简易 RPC 框架、简易连接池 — 展示对底层原理的理解
2. **压测与调优记录**：用 JMeter 压测，记录 JVM 调优、SQL 优化、缓存命中率等数据
3. **监控与告警**：接入 Prometheus + Grafana，展示线上问题排查能力
4. **容灾演练**：模拟缓存雪崩、服务宕机等场景，展示高可用设计思维

## 五、一句话总结

> 一个好的面试项目 = **业务场景合理** + **技术栈覆盖广** + **每个模块都有深度可挖**
>
> 做功能时多问自己：**"这里如果并发量翻 100 倍会怎样？数据量翻 100 倍会怎样？"**
>
> 能回答好这两个问题，面试就稳了。
